# 低内存 Evernote 式原生编辑器内核设计

日期：2026-09-09

状态：已批准核心方向，待用户复核书面规格

范围：仅编辑器，不包含同步、搜索、笔记列表、Joplin 兼容或跨平台

## 1. 决策与纠偏

本阶段唯一目标是：以尽可能低的常驻内存，实现可验证的 Evernote 核心所见即所得编辑行为复刻。

此前的 AppKit `NSTextView` 路线已经证明不适合本产品。它把富文档投影成一条属性字符串，再通过附件和多次投影维持结构，导致图片前后输入、列表、工具栏命令、焦点、自动保存和重排互相干扰。继续在该路径上补丁式修复，不再属于本设计。

本设计同时停止考虑以下约束：

- Joplin 数据模型、Markdown 往返、Joplin Server、官方 Android 客户端和 Data API；
- Tauri、WebKit、Electron、Node sidecar；
- 首轮同步、搜索、OCR、多模态索引、笔记本与标签；
- 为潜在 Windows、Linux 或移动端预先牺牲 macOS 编辑体验。

现有 AppKit 客户端和历史规格保留作实验记录，但不得作为新编辑器的实现基础。新内核采用 GPUI；Velotype 是可审计、可选择性提取的代码供体，不是直接换皮的应用模板。Evernote 和 ProseMirror 只作为交互行为与验收参照，不进入运行时。

## 2. “完美复刻”的可验证定义

“完美复刻”不是复制 Evernote 的全部产品功能、专有代码、商标或图形资产，而是复刻其核心编辑器的使用结果：用户不需要理解底层格式，文字、列表和图片都像同一篇文档中的一等内容，任何格式操作都立即、稳定、可撤销。

首个可验收版本必须满足：

1. 中文输入法组合文本、候选窗、提交、取消和连续输入稳定；
2. 光标可以落在图片前后，插入图片后立即出现在当前位置，不切换笔记、不闪跳；
3. 可连续跨越段落、标题、列表和图片进行鼠标选择、键盘选择、复制、剪切、删除和撤销；
4. 粗体、斜体、下划线、删除线、高亮、链接、段落样式、项目符号、编号与勾选列表均由同一事务系统实现；
5. 工具栏状态来自当前选区，所有可见按钮都必须真实可用；
6. `Command-A`、方向键、Home/End、删除、回车、粘贴和撤销行为连续，不因块边界形成焦点孤岛；
7. 长文档滚动时只排版可见区域，图片解码受硬预算约束；
8. 无 WebKit、JavaScript 引擎或额外 renderer 进程。

## 3. 技术选择

### 3.1 主框架：GPUI

GPUI 提供 GPU 原生渲染、窗口和输入事件、平台 IME 桥、文本排版接口以及适合编辑器的低层元素模型。新编辑器固定一个经过验证的 GPUI revision，并通过内部适配层隔离上游 API 变化。

不直接基于 wgpu/softbuffer 开始。直接渲染理论上能再减少少量框架开销，但需要同时重建窗口、输入法、剪贴板、焦点、无障碍、菜单和测试基础设施，反而降低实现正确编辑体验的概率。

### 3.2 Velotype 的使用边界

允许审计并提取：

- GPUI `EntityInputHandler` 与 UTF-16/UTF-8 范围转换；
- 字形布局、坐标到字符、字符到矩形的映射；
- 键盘命令路由、光标绘制与闪烁；
- 选区绘制、图片加载和部分跨块交互测试；
- Apache-2.0 许可允许使用的独立实现。

不得直接继承：

- Markdown 作为事实源、源码映射和 raw Markdown 回退；
- 为每个块建立独立输入焦点的架构；
- Velotype 的工作区、主题、导出、网络和完整应用外壳；
- 未通过本设计验收矩阵的 IME、跨块选择或图片行为。

### 3.3 cosmic-text、Makepad 与 Web 编辑器

`cosmic-text` 只允许作为 GPUI 文本栈的底层依赖或局部排版服务，不承担文档模型、编辑事务或块布局。

Makepad 当前具有优秀的 GPU UI、IME 基础和富文本渲染部件，但没有可直接复用的完整结构化富文本编辑器。首轮不同时建设 Makepad 版本。

ProseMirror/Evernote 用于列出行为、录制操作序列并进行同题对照；它们不通过 WKWebView 嵌入新应用。已经完成的 Evernote 逆向不是废弃材料，而是新内核的正式设计输入；其中被 AppKit/Joplin 约束污染的旧实现结论作废，观察证据与可复用机制继续有效。

### 3.4 Evernote 逆向成果的采用方式

现有 [`docs/research/evernote-11.32.5-targeted-reverse.md`](../../research/evernote-11.32.5-targeted-reverse.md) 是本设计的证据基线。它记录了本机 Evernote 11.32.5、`@evernote/common-editor` 183.272.12 source map 和本地结构的只读检查。后续实现必须采用下列已经确认的机制，而不是只模仿截图：

- **事务与变更生命周期**：区分用户内容事务、序列化、状态重置和显式 flush；即时发出 dirty/content-changed，空闲后再发出 settled，并允许未完成图片操作延后 settled；
- **CompositionSafeInput**：组合输入期间不以外部模型值覆盖正在输入的文本；组合结束后提交最小变更；焦点丢失时处理卡住的 composition 状态；
- **单一命令目录**：固定工具栏与 More 菜单共享同一套 execute、available、active/mixed 查询，不产生两份处理器或 UI 自有格式真相；
- **焦点与选区保护**：工具栏和普通弹层的 pointer-down 不清空文档选区；需要输入 URL 的控件是明确例外；命令完成后恢复编辑器焦点；
- **结构化图片节点**：图片保存自然尺寸和可选显示宽度，显示高度由纵横比计算；加载、错误、选择和缩放属于节点视图状态；正文不保存图片字节；
- **明确的相邻块间距**：段落到图片、标题到图片、图片到段落和图片到图片分别定义布局规则，图片不得继承标题行高；
- **视口有界工作**：保存可视文档位置并通过事务映射位置；只更新视口与小范围预取区；滚动和布局改变不导致全文重建；
- **内容宽度与底部空间**：正文采用有上限的居中书写宽度，窄窗使用可用宽度；底部保留约视口 30% 的滚动空间，使最后一行可以进入舒适编辑位置；
- **表现层与文档分层**：结构化编辑状态、协作状态和可读序列化是不同层，任何一层都不能被迫同时承担全部职责。

这些机制需要逐项映射到 GPUI 模块、事务类型和回归测试。逆向文档中的旧“Native ruling”若指定 AppKit、TextKit、Joplin HTML、SQLite 保存或 Loro，同本规格冲突时仅保留其上方 Evernote 观察，不继承旧结论。

继续逆向只针对尚不明确且直接影响编辑器的问题，例如列表边界退格、混合选区格式查询、图片 resize handles、富剪贴板优先级和组合输入跨块替换。每次检查必须记录 Evernote 版本、证据位置、观察结果、我们的原生裁决和对应测试；不得无目的解包全部应用，也不得复制专有源码或资源。

## 4. 总体架构

```text
Evernote 式编辑界面
        │ 命令 / 指针 / 键盘 / IME
        ▼
EditorCore（唯一焦点、唯一选区、唯一事务入口）
        ├── DocumentModel
        ├── SelectionModel
        ├── TransactionEngine
        ├── UndoManager
        └── CommandState
        │ 变更集 + 精确失效范围
        ▼
LayoutProjection
        ├── 可视块虚拟化
        ├── 文本塑形与命中测试
        └── 图片尺寸占位与异步解码
        ▼
GPUI / Metal 渲染
```

最重要的边界是：块是文档结构和渲染单元，不是独立文本编辑器。整个文档只有一个 `EditorCore` 持有焦点和选区；操作系统输入法只与当前活动文本位置交互，跨块选择仍由同一个编辑器状态管理。

## 5. 文档模型

### 5.1 块树

文档由稳定 `NodeId` 标识的块组成：

- `Paragraph`
- `Heading { level: 1..=3 }`
- `ListItem { kind, depth, checked }`
- `BlockQuote`
- `CodeBlock`
- `Image { resource_id, intrinsic_size, display_width, alt }`
- `Attachment { resource_id, filename, media_type }`
- `Divider`

列表在模型中保留类型、层级和连续关系，不依赖渲染时猜测相邻字符串。图片是正式节点，不使用对象替换字符或 RTF 附件占位符。

### 5.2 行内文本

每个文本块保存 UTF-8 文本和有序、无重叠规范化的 mark spans：

- bold
- italic
- underline
- strikethrough
- highlight
- link
- inline code

普通笔记优先使用紧凑 `String` 和小向量保存样式范围；只有性能测量证明超长单块编辑存在瓶颈时，才替换为 rope。不得为了理论规模预先承担 rope、CRDT 或持久不可变树的内存开销。

### 5.3 位置与选区

位置表示为 `DocPoint { node_id, utf8_offset, affinity }`。选区由 anchor/head 两个文档位置组成，可正向或反向跨块。图片前后是显式可落光标的文档位置，图片本身可作为原子节点被选择。

只有与 macOS IME 通信时才把活动块范围转换为 UTF-16；内部模型、事务和布局缓存统一使用 UTF-8 字节边界，并在 API 入口验证 grapheme 边界。

## 6. 编辑事务

所有输入和工具栏操作必须转换为原子事务：

- `InsertText`
- `DeleteRange`
- `SplitBlock`
- `MergeBlocks`
- `SetBlockKind`
- `ToggleMark`
- `SetLink`
- `InsertNode`
- `RemoveNode`
- `SetNodeAttrs`
- `IndentList` / `OutdentList`

事务在提交前验证位置和结构，成功后一次性更新文档、选区、撤销记录和布局失效范围。渲染层不得直接修改文本，工具栏也不得调用平台富文本 API 绕过模型。

连续键入按时间和选区连续性合并成一个撤销步骤。撤销保存反向操作，不保存整篇快照；历史记录同时受步骤数和字节数限制，初始预算为 1,000 步或 16 MiB，先达到者触发最旧记录回收。

首轮不引入 Yjs、Loro、Automerge 或其他 CRDT。事务接口保留稳定的变更集输出，但不得让同步需求进入输入热路径。

## 7. 输入法与统一焦点

`EditorCore` 是唯一 GPUI 输入处理实体。它负责：

1. 把 macOS 提供的 UTF-16 selection/marked range 映射到当前活动文本块；
2. 在组合期间保存 marked range，但不破坏现有 mark spans；
3. 组合提交后生成一次可撤销事务；
4. 组合被取消、焦点丢失或结构命令触发时，以明确规则提交或撤销；
5. 跨块选区收到输入时，先在一个事务中删除选区，再在起点插入组合文本。

块切换不得创建新的平台输入对象。工具栏点击需要保留编辑器焦点和选区；命令执行结束后光标仍停留在预期文档位置。

## 8. 布局与渲染

### 8.1 可视块虚拟化

`LayoutProjection` 只为视口和上下预取窗口内的块创建精确布局。远离视口的块只保存估算高度和文档数据，不持有 GPUI entity、字形 run、选择矩形或 GPU 资源。

文本布局缓存以 `(NodeId, node_revision, width, style_revision)` 为键。事务只失效受影响的块；改变一个字符不得重新塑形整篇文档。

### 8.2 图片插入

图片插入流程：

1. 在当前选区处提交结构事务；如果光标位于段落中间，则拆成“前段落—图片—后段落”；
2. 立即创建图片节点，并从文件头读取尺寸，生成稳定纵横比占位；
3. 后台按实际显示尺寸解码缩略图；
4. 解码完成只替换纹理，不改变已有占位高度；
5. 原图仅在用户进入查看/缩放模式时按需解码。

这条链确保缩略图和编辑区共享同一资源事实，但拥有彼此独立的显示缓存；编辑区不需要通过切换笔记重新读取数据。

### 8.3 GPU 与图片缓存

图片缓存按解码后的像素成本计算，不按压缩文件大小计算。CPU bitmap 与 GPU texture 分别使用 LRU，默认合计硬预算 48 MiB；离开视口的原尺寸纹理优先回收。图片列表缩略图不得复用正文大纹理。

字形 atlas 和布局缓存同样设定可观测预算，不能只依赖操作系统内存压力通知。

## 9. 工具栏与 Evernote 式交互

工具栏是 `EditorCore` 命令的视图，不保存独立格式状态。每次选区变化后，通过 `CommandState` 查询：

- 当前块类型；
- 行内格式是开启、关闭还是混合；
- 命令是否适用；
- 列表层级能否增加或减少；
- 撤销与重做是否可用。

首屏工具栏保留段落样式、撤销/重做、粗体、斜体、下划线、高亮、项目符号、编号、勾选列表、链接、对齐和更多菜单。按钮只有两种合法状态：真实可用，或者明确禁用；禁止出现可点击但没有任何效果的占位功能。

Evernote 的视觉密度、顺序、留白和反馈作为参考，但图标和资产重新设计。首轮不实现 AI、协作、任务中心、日历、网页书签和其他非编辑本质功能。

## 10. 内存与性能预算

以下数字是发布门槛，不是未经测量的完成声明；统一在指定 Apple Silicon 测试机、Release 构建、窗口稳定 30 秒后测量：

- 空白编辑器单进程 RSS：不超过 80 MiB；
- 200 个文本块、10 张普通图片的典型笔记，稳定 RSS：不超过 120 MiB；
- 10,000 个纯文本块加载后，相比空白编辑器新增 RSS：不超过 40 MiB；
- CPU bitmap + GPU texture 缓存默认预算：48 MiB；
- 文本布局缓存默认预算：16 MiB；
- 撤销历史默认预算：16 MiB；
- 普通键入事务到提交 P95：低于 8 ms；
- 可视重排与绘制提交 P95：低于 16 ms；
- 单字符编辑不得产生与全文长度线性相关的临时分配。

测试报告同时记录 RSS、堆分配、Metal 纹理估算、峰值与稳定值，避免只测进程列表中的一个数字。超过预算时先定位缓存、纹理和重复文档副本；不得通过关闭正确输入、撤销或图片显示来伪造低内存结果。

## 11. 错误处理

- 非法事务不进行部分提交，返回结构化错误并保留原文档和选区；
- 图片解码失败时保留可选中的图片节点、文件名和重试入口，不删除资源引用；
- GPU 纹理创建失败时降级为受尺寸约束的占位显示，但编辑事务继续工作；
- 布局缓存可以完全丢弃和重建，不能成为文档事实源；
- 输入法范围不合法时取消本次平台更新并记录脱敏诊断，不猜测偏移后改写文字；
- panic 不得跨越编辑事务边界造成半更新状态。

## 12. 验证策略

### 12.1 行为夹具

以 Evernote 当前编辑器建立同题操作夹具，记录输入、选区、命令、最终结构和屏幕结果。夹具至少覆盖：

- 中文拼音长组合、候选翻页、组合中移动光标和退格；
- 段落中间插图、图片前后继续输入、连续插入两张图片；
- 文字—图片—文字跨块选择、复制、删除与撤销；
- 普通段落和三种列表互转、嵌套与退格退出列表；
- 混合格式选区的工具栏状态；
- 富文本和图片从剪贴板粘贴；
- 10,000 块长文档滚动和尾部编辑。

### 12.2 自动化测试

- 文档模型与事务的单元测试；
- 随机操作序列的结构不变量和撤销往返属性测试；
- UTF-8/UTF-16/grapheme 范围转换测试；
- 跨块选择、图片边界和列表转换回归测试；
- 布局缓存精确失效测试；
- 图片缓存 LRU 与硬预算测试；
- GPUI headless/test-support 下的输入与命令测试。

### 12.3 真机验收

自动化不能替代 macOS 输入法和真实渲染验收。每个阶段都必须在 Release 应用中使用系统中文输入法、Finder 拖拽、截图复制、Photos/Preview 复制和长文档滚动进行目视复核，并用 Instruments 验证内存稳定性。

## 13. 实施边界与停止条件

正式实现前先做一个可丢弃的 GPUI 技术验证，只验证统一输入、跨块选择、列表和图片边界。若技术验证不能同时达到以下条件，不继续扩展 UI：

- 中文 IME 无丢字、重字和候选窗错位；
- 图片前后输入与跨块选择稳定；
- 工具栏命令只通过事务改变模型；
- 空白与典型文档内存进入本设计预算；
- 不依赖 WebKit 或多进程运行时。

技术验证通过后，代码才进入正式编辑器模块。任何为了赶进度而恢复 `NSTextView`、每块独立输入框、Markdown 事实源或全量图片解码的方案，都视为违反本设计。

## 14. 取代关系

本规格仅取代此前与编辑器实现有关的 AppKit、RTF、HTML/Joplin 兼容和 Tauri/WebKit 决策。现有仓库中的其他功能不会在本阶段迁移或删除；它们也不能反向限制新编辑器内核。

后续若重新讨论存储、同步、搜索或完整应用外壳，必须把编辑器作为已定义接口的独立组件接入，不得把这些需求重新塞回编辑输入热路径。
