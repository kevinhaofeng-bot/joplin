# Joplin Lite 设计说明

日期：2026-09-03  
状态：已批准，待实施  
目标用户：单人自用

## 1. 背景与决策

现有 Joplin 数据和工作流已经稳定使用多年，但有四个持续问题：

1. WebDAV 维护会造成周期性同步失败，故障状态和恢复过程不够透明。
2. 桌面端编辑手感弱于 Evernote，默认编辑路径不符合所见即所得习惯。
3. 搜索能力偏弱，尤其是中文、图片和扫描 PDF。
4. Electron 携带 Chromium，应用体积和常驻内存偏大。

当前资料库包含 1662 篇有效笔记、31 个笔记本、64 个标签和 4238 个资源，附件逻辑大小约 1.1 GiB，其中 141 个 PDF，并有 7 个附件超过 20 MiB。两台 Android 设备继续使用官方 Joplin 客户端，微信收藏导入继续依赖 Joplin Data API。

项目采用“兼容内核逐步替换”的路线：在用户自己的 Joplin fork 中新增轻量 macOS 客户端，不立即重写或删除官方稳定路径。第一阶段复用官方同步、加密和数据模型实现，待兼容性测试完备后再逐步替换成 Rust。

不选择以下路线：

- 继续改造 Electron 桌面端：不能从根本上解决应用体积和 Chromium 常驻开销。
- 一次性纯 Rust 重写全部 Joplin：同步协议、E2EE、冲突处理、移动端互通和编辑器语义同时重写，数据风险过高。
- 迁移至其他笔记产品：会破坏现有资料库、Android 客户端和微信导入链，并不能同时满足简单、可靠、自托管、多模态和低资源占用。

## 2. 设计原则

1. **数据优先**：任何优化都不能以笔记或附件丢失、静默改写为代价。
2. **兼容优先**：第一版必须和官方 Joplin Android、Joplin Server、E2EE 及现有 Data API 工具互通。
3. **默认简单**：常用操作直接可见，低频设置收进高级区域，不复制完整 Joplin 桌面端的功能面。
4. **本地优先**：编辑、全文搜索、OCR 和语义索引默认在 Mac 本地完成。
5. **渐进替换**：稳定能力先作为适配器保留；只有通过固定样本和多客户端回归后，才允许由 Rust 实现接管。
6. **单写迁移**：WebDAV 和 Joplin Server 不做双向双写。迁移过程中始终只有一个同步源可写。

## 3. 首版范围

### 3.1 包含

- macOS 原生窗口和菜单体验。
- 默认所见即所得编辑器。
- 笔记、待办、笔记本、标签、附件和基本历史版本。
- 离线编辑、同步状态、错误详情、手动重试和冲突入口。
- 标题、正文、标签、附件文本、OCR 文本的统一搜索。
- 图片和 PDF 页面的本地语义搜索。
- 与现有微信收藏导入工具兼容的本地 Joplin Data API 子集。
- Joplin Server 同步和端到端加密。
- 从现有 WebDAV 同步目标安全迁移到 Joplin Server。

### 3.2 不包含

- 插件市场和第三方桌面插件兼容层。
- 多用户协作、公开分享、笔记发布和团队权限。
- 同时维护 Markdown、富文本等多套平级编辑模式。
- 大量主题、布局和工具栏自定义。
- 首版直接用 Rust 重写 Joplin 同步协议或加密格式。
- 修改 Joplin Server 源码；服务端使用官方固定版本镜像。

## 4. 总体架构

项目暂用工作名 `Joplin Lite`，在 monorepo 中新增 `packages/app-lite`。现有官方包不删除、不改名，稳定路径保持可构建。

```text
┌──────────────────────── macOS：Joplin Lite ────────────────────────┐
│ Tauri/WebKit UI                                                    │
│  ├─ 笔记列表与所见即所得编辑器                                    │
│  ├─ 搜索与同步状态                                                 │
│  └─ 设置、冲突与恢复界面                                           │
│                                                                    │
│ Rust Core                                                         │
│  ├─ 本地数据库访问与任务调度                                       │
│  ├─ Tantivy 全文索引                                               │
│  ├─ OCR/PDF/多模态索引                                             │
│  ├─ 附件与缓存管理                                                 │
│  └─ 本地 Data API 兼容层                                           │
│                                                                    │
│ @joplin/lib Sync Adapter（首版独立 sidecar）                       │
│  ├─ Joplin 数据序列化                                              │
│  ├─ E2EE                                                           │
│  ├─ 冲突与同步状态机                                               │
│  └─ Joplin Server API                                              │
└──────────────────────────────┬─────────────────────────────────────┘
                               │ TLS + E2EE 数据
                     ┌─────────▼─────────┐
                     │ 日本 VM 101       │
                     │ Joplin Server     │
                     │ PostgreSQL        │
                     └─────────┬─────────┘
                               │ 单向加密备份
                     ┌─────────▼─────────┐
                     │ NAS 恢复副本      │
                     └───────────────────┘
```

### 4.1 进程边界

- UI 进程只负责展示和编辑交互，不直接实现同步协议。
- Rust Core 是本地权威协调者，持有任务状态、搜索索引和附件处理队列。
- 同步 sidecar 使用版本固定的 Node 运行环境和 `@joplin/lib`，通过受限的本地 IPC 接收命令。
- sidecar 崩溃不会带走编辑器进程；Rust Core 记录最后成功游标和错误，并允许单独重启。
- sidecar 不开放网络监听端口；只有 Data API 兼容层监听回环地址。

## 5. 数据与兼容性

### 5.1 本地资料库

首版不直接在用户正在使用的 `~/.config/joplin-desktop` 上开发或试写。测试和迁移使用独立 profile；正式切换前执行一致性校验。

本地数据模型遵守 Joplin item、resource、revision 和 encryption item 语义。新增的 OCR、向量、任务队列及 UI 状态放在独立数据库或明确命名的扩展表中，不写入同步协议不认识的字段。

### 5.2 所见即所得编辑器

编辑器以 Joplin Markdown 为持久化格式，以结构化文档模型驱动所见即所得交互：

- 常用标题、列表、待办、表格、引用、代码、链接、图片和附件可视化编辑。
- 粘贴图片立即显示本地预览，附件入库和同步异步完成。
- 自动保存采用短延迟批处理，并在窗口关闭或切换笔记前强制刷盘。
- 对无法安全往返转换的 Markdown、HTML 或插件语法，使用“原文保留块”。用户可以查看或编辑源文本，但富文本操作不会重写其内部内容。
- 保存前进行一次往返保护检查；如果结构丢失，拒绝覆盖并保留恢复副本。

### 5.3 Data API

兼容层默认尝试 Joplin 桌面端常用的 `41184–41194` 回环端口，仅绑定 `127.0.0.1`，支持现有微信导入所需的：

- token 验证；
- notes、folders、tags、resources 的读取和创建；
- multipart 附件上传；
- ping、分页和常用字段选择。

旧脚本中硬编码的 API token 在迁移时轮换，新凭据存入 macOS Keychain；代码和日志不得保存明文 token。

## 6. 同步与服务端

### 6.1 为什么使用 Joplin Server

Joplin Server 相比通用 WebDAV 提供面向 Joplin 的增量游标、批量操作和更准确的时间戳语义，减少目录扫描、属性差异和 WebDAV 服务维护造成的不确定性。它仍不是“绝不会失败”，因此客户端必须把断网、服务重启、游标失效和部分上传视为正常可恢复状态。

服务端源码可见，但 `packages/server` 使用个人用途许可证而非项目根目录的 AGPL 许可。当前用途是个人自托管，符合本项目范围；不修改或再分发服务端代码。

### 6.2 部署拓扑

- 日本 VM 101：Docker Compose 运行固定版本的 Joplin Server 和 PostgreSQL。
- PostgreSQL 仅连接内部 Docker 网络，不发布宿主机端口。
- Joplin Server 通过现有 TLS 入口对外提供服务。
- 数据库和资源数据位于 VM 本地磁盘，避免把运行时数据库放在 NFS 上。
- NAS 接收数据库 dump、配置清单和资源备份；备份传输和静态文件均加密。
- 恢复演练使用隔离实例，不直接覆盖生产目录。

### 6.3 WebDAV 迁移

1. 冻结切换窗口，先让现有客户端完成一次 WebDAV 同步。
2. 备份本地 profile、WebDAV 服务端目录和数据库清单。
3. 部署 Joplin Server，并用独立测试 profile 验证登录、附件和 E2EE。
4. 选择一台权威客户端上传完整资料库到 Joplin Server。
5. Android 设备逐台切换，完成全量同步和计数/哈希抽检。
6. 新客户端最后加入，进行多客户端编辑和冲突测试。
7. 旧 WebDAV 改为只读保留至少 30 天；不再接受客户端写入。

## 7. 搜索与多模态索引

### 7.1 索引管线

Rust Core 维护可重建的派生索引：

1. 提取标题、正文、标签、时间和笔记本元数据。
2. 对 PDF 优先提取原生文本；文本不足时按页 OCR。
3. 对图片执行本地 OCR，并生成图片语义表示。
4. 对 PDF 页面生成可定位的语义片段。
5. 写入 Tantivy 倒排索引和独立向量索引。

原始笔记和附件是唯一事实源；OCR 和向量索引损坏时可以完全重建。

### 7.2 查询融合

搜索结果融合以下信号：

- Tantivy BM25 全文相关性；
- 标题、标签和笔记本字段加权；
- 中文分词及连续字符匹配；
- 语义向量相似度；
- 最近编辑时间的轻量衰减加权。

每个结果必须说明命中位置：正文、标签、图片 OCR、PDF 页码或语义匹配。语义结果不能伪装成文字精确命中。

### 7.3 资源控制

- OCR 和向量模型独立下载，不计入基础应用包。
- 首次索引可暂停、限速，并默认只在接电或用户允许时高负载运行。
- 模型按需加载，空闲后卸载。
- 文件哈希和模型版本决定是否重建，避免重复处理未变化附件。

## 8. 故障处理和数据保护

- 所有编辑先原子写入本地，再进入同步队列；网络失败不阻塞继续编辑。
- 同步操作使用持久化任务状态，可在进程重启后恢复。
- 上传附件采用内容哈希校验；未确认服务端存在前不得清理本地文件。
- 删除进入延迟清理队列，至少经过一次成功同步和宽限期后才清理派生缓存。
- 冲突保留双方副本，并在 UI 中显示来源设备和修改时间，不做静默覆盖。
- 连续失败采用有上限的指数退避；用户主动同步可立即重试。
- 同步界面显示阶段、最后成功时间、待处理项目、失败项目和可复制的脱敏诊断。
- 日志不得记录正文、附件内容、密码、E2EE 主密钥或 API token。
- 数据库迁移先备份并使用事务；失败时自动回滚到旧 schema。

## 9. 性能目标

首版目标，不作为牺牲数据正确性的理由：

- 基础安装包不含可选模型时小于约 100 MiB。
- 常驻空闲 RSS 目标低于 250 MiB。
- 普通笔记键入在本机上无可感知卡顿，编辑事务的 P95 处理时间低于 50 ms。
- 已建立索引后的常规关键词查询 P95 首屏低于 150 ms。
- OCR/向量后台任务可暂停，不应让前台输入出现持续掉帧。

## 10. 验证与验收

### 10.1 自动化测试

- Rust 单元测试：任务状态机、索引、查询融合、附件哈希、API 鉴权和脱敏日志。
- 编辑器往返测试：官方 Markdown 样本、HTML 块、表格、待办、内部链接、资源链接及未知语法。
- 同步契约测试：使用固定 fixtures 对比官方 `@joplin/lib` 的序列化、加密和冲突结果。
- API 契约测试：运行微信收藏导入路径所需的真实请求序列。
- 服务端集成测试：临时 Joplin Server/PostgreSQL 容器执行创建、修改、删除、附件、E2EE 和游标恢复。
- 故障注入：断网、超时、sidecar 崩溃、服务端重启、磁盘空间不足和重复请求。

### 10.2 数据验收

- 1662 篇有效笔记、31 个笔记本、64 个标签、4238 个资源及关联关系完成计数核对。
- 所有附件按内容哈希核验；7 个大于 20 MiB 的附件单独验证。
- 抽取普通文本、复杂 Markdown、图片、PDF、DOCX 和历史笔记进行目视复核。
- 两台 Android 和 Mac 新客户端分别完成创建、编辑、删除、附件和离线恢复测试。
- E2EE 开启状态下完成新设备初始化、密钥解锁和跨设备读取。
- 中文、标题、标签、图片文字、扫描 PDF 和语义描述建立固定搜索评测集。

### 10.3 发布门槛

实验阶段使用独立 profile 和测试服务端。满足自动化测试与一次完整迁移演练后，进入并行观察；正式替换 Electron 客户端前，Joplin Server 至少稳定运行 30 天。观察期内保留官方客户端和只读 WebDAV 数据作为恢复路径。

## 11. 实施阶段

1. **基线与夹具**：记录当前资料库统计，建立同步、编辑、API 和搜索兼容样本。
2. **服务端先行**：部署并备份 Joplin Server/PostgreSQL，完成隔离恢复演练。
3. **应用骨架**：Tauri/Rust 外壳、独立 profile、数据库、sidecar 生命周期和同步状态。
4. **核心编辑体验**：列表、笔记本、标签、附件和默认所见即所得编辑器。
5. **兼容链**：Data API、E2EE、Android 互通、冲突与故障恢复。
6. **搜索增强**：Tantivy 中文全文检索，再加入 OCR 和多模态索引。
7. **迁移与观察**：全量演练、设备逐台切换、30 天稳定性观察。
8. **渐进 Rust 化**：只在协议 fixtures 和双实现对照测试通过后替换具体同步模块。
