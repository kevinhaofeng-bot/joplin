# Joplin 现用资料库：只读元数据资格盘点（2026-09-13）

本页只是对当前 Joplin Desktop SQLite 做 `mode=ro` 聚合查询；没有导出 JEX、读取笔记正文或标题、复制/修改资料库，也不构成迁移验收。资料库仍由 Joplin 使用，数字可能继续变化。JEX 的实际字段和资源文件必须以独立导出的副本重新验证。开源 Joplin `InteropService.ts::export` 从各 folder 的 `noteIds` 选择笔记，按正文链接选资源，并只导出所选笔记的 note-tag/tag；`Folder.notes` 默认排除 `deleted_time != 0`。因此 SQLite 总量与普通 JEX 的数量**不能直接相等比较**，特别是回收站和未被正文引用的资源。

另一个直接从源码可见的兼容边界：`BaseItem.ts::serialize` 默认逐个写出模型的 `fieldNames()`，包括值为空或零的字段；现有 Rust JEX stage 只接受窄字段白名单。因此合成小样本能入库，**不能推断当前 Joplin 导出的真实 JEX 可直接入库**。后续须对真实 JEX 副本统计每类字段/正文/资源的 blocker，再把可保真的字段逐项映射或保留为明确可恢复的审计元数据。

下一步不是直接把当前隔离 stage 换进正式资料库：先完成 type 5/6 标签与关联，再对实际 JEX 副本做只读资格/阻断分布扫描，明确待办、已删除、来源 URL、排序与混合根文件夹的保真策略；补合成回归后再考虑可恢复的资料库切换、导出与实际接受测试。
